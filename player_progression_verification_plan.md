# Player Progression System Verification Plan

This plan outlines the steps to verify the implementation of the Player XP and Progression System based on the `player_progression_plan.md`.

## 1. Review XP Earning Mechanics (Match Engine)
*   **File:** `src/routes/match/+page.svelte`
*   **Action:**
    *   Examine the `playerStatsUpdates` object and the logic that populates it.
    *   Verify that all XP reward rates defined in `player_progression_plan.md` are accurately calculated and added to the `xp` property of `playerStatsUpdates` for each player.
        *   Participation: +10 XP
        *   Batting: +1 XP per run, +50 XP for Half-Century, +100 XP for Century
        *   Bowling: +15 XP per wicket, +50 XP for 3-wicket haul, +100 XP for 5-wicket haul
        *   Fielding: +10 XP per catch/stumping, +15 XP for run-out
        *   Match Awards: +100 XP for Player of the Match
    *   Confirm that `playerStore.updatePlayerStats(id, playerStatsUpdates[id])` is correctly called at the end of the match resolution, passing the calculated XP.

## 2. Verify Player Data Model and Generation
*   **File:** `src/lib/models/player.ts`
*   **Action:** Confirm that the `Player` interface includes `xp: number` and `lifetimeXp?: number`. (Already checked, appears to be implemented).
*   **File:** `src/lib/core/draftAI.ts` (or `playerGeneration.ts`)
*   **Action:** Confirm that new players generated by `generatePlayer` function are initialized with `xp: 0` (and `lifetimeXp: 0` if applicable). (Already checked, appears to be implemented).

## 3. Verify Stat Upgrade Mechanics (Stores)
*   **File:** `src/lib/stores/gameState.ts`
*   **Action:**
    *   Examine the `upgradePlayerStat` function.
    *   Verify that it correctly deducts `xpCost` from the player's `xp` and `creditCost` from the team's budget.
    *   Ensure that the target stat is incremented by 1, and that the stat cannot exceed 100. (Already checked, appears to be implemented).

## 4. Verify UI Updates

### 4.1. Post-Match Summary
*   **File:** `src/routes/match/+page.svelte`
*   **Action:** Check the post-match player performance summary UI for an "XP Earned" column or a clear display of XP gained by each player in the summary table.

### 4.2. Player Modal
*   **File:** `src/lib/components/team/PlayerModal.svelte`
*   **Action:**
    *   Confirm that the player's current XP is prominently displayed.
    *   Verify the presence of `[+]` buttons next to each upgradable stat (Batting, Bowling, Power, Technique, Fielding).
    *   Check that hovering over or clicking these `[+]` buttons correctly shows the required XP and Credit cost for the next level. (Already checked, appears to be implemented).

### 4.3. Squad/Dashboard Views
*   **File:** `src/lib/components/team/PlayerCard.svelte`
*   **Action:** Verify that the `canUpgradeAny` derived property is used to provide a visual indicator (e.g., a special icon, border, or glow) on player cards for players who have enough XP and team budget to afford at least one upgrade. (Already checked `canUpgradeAny` exists, need to verify its visual usage).
